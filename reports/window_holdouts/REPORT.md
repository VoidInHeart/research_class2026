# 窗口长度对开放集意图识别与执行路由的影响

2026-11-18，SGD 本地离线实验。**最近 5 条发言在两种编码器、四种留出设置中都提高了已知意图 Top‑1 准确率和 OOS 平衡准确率。端到端完整调用成功率没有一致提升。** 在最难的近域购票组，MiniLM 的未知召回甚至下降。若目标是识别当前意图，最近 5 条是三种设置里优先考虑的基线；若目标是把未知意图可靠送去兜底，还需要单独确定可接受的已知误拒与未知漏放水平。

## 怎样比较

使用 10 个既有 SGD 分片，保留对话全程以及长、短窗口规范化重复模板的分组边界。对每种编码器、每组留出，先固定识别器的拟合集、路由监督集、校准集和测试集，再更换窗口。短窗口取当前用户发言及之前最多四条用户或系统发言。原窗口使用截至当前轮的全部对话，MiniLM 超长时从左边截断，保留最后 256 token。三种设置如下。

| 设置 | OOS 门控读取 | 输出已知意图向量时读取 |
|---|---|---|
| 原窗口 | 原窗口 | 原窗口 |
| 最近 5 条 | 最近 5 条发言 | 最近 5 条发言 |
| 长短双窗口 | 原窗口 | 最近 5 条发言 |

TF-IDF 的词表及两种编码器的意图原型均只用本组拟合集；MiniLM 使用已有本地权重。每种窗口只在本组校准集选择最大余弦相似度阈值，以已知接受率和未知召回的平均值为目标；向量的温度只按校准集中的已知请求拟合。双窗口复用原窗口的阈值和短窗口的意图向量，二者接口与原系统一致。所有设置在 OOS 时直接走兜底，放行时将已知意图向量传给同一张能力矩阵。矩阵由本组路由监督集的真实已知意图和三个专家的冻结成功记录拟合，在同组的三个窗口间保持一致。

整个实验共用此前保存的三个检索执行器和通用检索兜底，执行器始终读取原始对话。用原 1,852 个专家拟合样本和已保存配置恢复专家池，一次离线重放 2,228 个拟合集外的请求。原实验 1,076 条测试请求的四个原始调用逐条相同，598 条路由监督的成功标记也全部匹配。分别把 TF-IDF、MiniLM 原窗口用于原留出组时，1,076 条测试上的首选意图、门控、矩阵选中的执行器和评分均复现旧记录。没有调用模型或业务 API。[窗口实现](../../intentexec/window_scoring.py) · [执行器核验](../../intentexec/window_frozen.py)

## 留出了哪些意图

四组均使用原 fit 的子集拟合第一层，只使用原 router 的子集构建能力矩阵。校准和测试只在原 cal/test 的对话池内按当前未知标签划分。出现其他未纳入目录的意图、同时涉及本组两类留出或引起跨分割模板重复的对话组件均隔离。拟合组里失去样本支持的意图按规则排除。组别及近域对照按意图和样本覆盖确定，未根据模型成绩挑选。

| 校准未知 → 测试未知（实际有样本） | 已知意图数 | 拟合 / 路由监督 | 校准数 | 测试已知 / 未知 |
|---|---:|---:|---:|---:|
| 电影检索和场次 → 余额查询、天气（原组） | 17 | 1,852 / 598 | 554 | 820 / 256 |
| 查歌和播放 → 公交查询和购票 | 11 | 532 / 128 | 188 | 174 / 80 |
| 查航班和订航班 → 查询和预订住宿 | 11 | 888 / 290 | 193 | 162 / 54 |
| 余额查询 → 公交购票，保留公交查询为已知 | 16 | 1,307 / 447 | 544 | 377 / 69 |

各组最终未知意图均未参与本组第一层拟合、路由监督和阈值校准。为了严格固定执行器，新增三组的测试未知意图曾经出现在旧专家拟合集；原组的测试未知在旧专家拟合集也完全留出。因此新增三组用于评估**第一层遇到新意图，以及在既定执行池上的分流结果**。不同组的测试集两两有 134 到 328 条请求重叠，表中不跨组合并样本或做总体显著性检验。[留出配置](../../configs/window_holdouts.json) · [分组清单及逐类暴露计数](folds.json)

## 各组结果

每格三个数依次给出 **原窗口 / 最近 5 条 / 双窗口**。前两项为百分比，最后一项为完整调用正确条数。已知 Top‑1 在所有真实已知请求上计算，包括被门拒绝的请求。OOS 平衡准确率等于“已知接受率与未知召回率的平均值”。完整调用要求服务、方法、全部参数均正确。

| 编码器 | 留出组 | 已知 Top‑1（%） | OOS 平衡准确率（%） | 完整正确数 / 测试总数 |
|---|---|---|---|---|
| MiniLM | 原组 | 84.02 / 88.90 / 88.90 | 59.87 / 80.55 / 59.87 | 88 / 83 / 72（共 1,076） |
| MiniLM | 音乐 → 公交 | 86.21 / 90.23 / 90.23 | 76.36 / 79.44 / 76.36 | 12 / 13 / 13（共 254） |
| MiniLM | 航空 → 住宿 | 87.04 / 97.53 / 97.53 | 79.63 / 86.11 / 79.63 | 21 / 22 / 21（共 216） |
| MiniLM | 余额 → 公交购票 | 61.80 / 73.74 / 73.74 | 48.66 / 52.68 / 48.66 | 39 / 34 / 39（共 446） |
| TF-IDF | 原组 | 73.78 / 85.00 / 85.00 | 70.19 / 80.73 / 70.19 | 84 / 82 / 86（共 1,076） |
| TF-IDF | 音乐 → 公交 | 81.61 / 91.95 / 91.95 | 58.34 / 72.24 / 58.34 | 12 / 13 / 13（共 254） |
| TF-IDF | 航空 → 住宿 | 82.72 / 95.68 / 95.68 | 67.90 / 83.95 / 67.90 | 22 / 22 / 22（共 216） |
| TF-IDF | 余额 → 公交购票 | 50.40 / 64.72 / 64.72 | 51.41 / 60.34 / 51.41 | 39 / 37 / 38（共 446） |

**第一层识别。** 相对原窗口，短窗口在 MiniLM 上提高 4.02–11.94 个百分点，在 TF-IDF 上提高 10.34–14.32 个百分点。两种编码器各组的已知意图宏平均召回也均上升。原组 MiniLM 的 Top‑1 提升 4.88 个百分点，对话聚类配对 95% 区间为 [2.25, 7.63]；音乐 → 公交的对应区间下界为 0。双窗口和短窗口使用同一个意图向量，所以已知 Top‑1 逐条相同。

**OOS 门控。** 原组 MiniLM 从已知误拒 29.88%、未知召回 49.61%，变为误拒 19.76%、召回 80.86%。该组平衡准确率提高 20.69 个百分点，95% 区间为 [16.82, 24.62]。近域购票的情况不同：MiniLM 未知召回从 17/69 降为 9/69（24.64% → 13.04%），同时已知误拒从 27.32% 降为 7.69%，所以平均后的平衡准确率仍提高 4.02 个百分点，95% 区间为 [−2.36, 10.56]。其 OOS AUROC 从 0.638 升至 0.695，说明在这里排序能力和从校准域迁移来的阈值表现需要分别看。双窗口照用原窗口的门，门控结果逐条相同。

**最终路由。** 原组 MiniLM 短窗口救回 10 条完整调用，同时损失 15 条，净少 5 条（−0.46 个百分点，95% 区间 [−1.43, 0.46]）。有 70 条既有已知请求从首选意图错误变为正确，在这 70 条中只有 8 条有任一冻结执行器可以完全答对。双窗口在同组从 88 条降至 72 条（−1.49 个百分点，95% 区间 [−2.39, −0.74]）。在其余三组 MiniLM 上，短窗口相对原窗口分别净增 1、增 1、减 5 条。由此可见，已知意图识别改善能跨组复现，最终工具调用成功率没有相同的趋势。各组样本、已知目录、阈值和矩阵随留出方案变化，因此窗口效果应在组内配对解释。

每组的区间来自对话聚类的 2,000 次配对 bootstrap，反映固定专家、校准和当前留出组下的抽样不确定性。全部 24 组指标、每类表现、各窗口配对的救回/损失、阈值及能力矩阵见 [机器可读结果](results.json)。[11,952 条逐请求预测](predictions.jsonl.gz)

## 复现与核验

在仓库根目录运行。仅核验已提交的结果时，不需要下载 SGD 或加载 MiniLM。

```powershell
python -m intentexec.window_replay --run-dir reports/window_holdouts
```

重新做实验需要项目已有的 SGD 10 个分片、本地 MiniLM 权重以及原检索试点目录 `artifacts/verified-minilm`。缺少原试点目录时，可用仓库原有的 MiniLM + retrieval 全量试点命令生成；冻结程序会对照该目录的历史调用逐条核验。结果输出到一个新目录。

```powershell
python -m intentexec.window_experiment --out artifacts/my-window-holdouts
```
